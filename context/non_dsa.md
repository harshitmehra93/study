# System Design And Behavioral Tracker

This file owns compact evidence for System Design and Behavioral attempts.
`context/session_workflow.md` owns live behavior; `context/roadmap.md` owns only
priorities and meaningful readiness changes.

Append one row after newly demonstrated work. Status/history review and passive
discussion do not create rows. Use `yyyy-mm-dd` and the assistance vocabulary in
`context/startup_protocol.md`.

Use `Pass` when the requested work is complete and correct, `Partial` when
material work remains, `Miss` when no viable result is reached, and `Unknown`
when evidence is insufficient. Keep outcome, help, and timing separate.
